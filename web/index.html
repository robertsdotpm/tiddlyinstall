01  What it is

Real installers for Windows, Linux and macOS, straight from a GitHub repo.

No freezing and no bundlers that break. We install your project's real runtime and dependencies into a folder of its own, clone your project, and install it against them. The result is an ordinary installer built with NSIS on Windows and the Qt Installer Framework on Linux and macOS.

02  The unusual part

One file, like TiddlyWiki

TiddlyInstall is a single HTML file. This page carries the base installers, the runtime catalogue and all the code that makes, edits and signs installers. Save it (at the bottom of the page) and open it from your disk, and it keeps working with no server: it builds installers for code you write here or for packages, edits any unsigned installer, and signs with your own key. When a build server is there, it uses it for the rest: installers signed by us, GitHub repos, and installers with their runtimes packed inside.

03  How it works

Three steps, no surprises

Step one

Point at a repo

Give us a GitHub repository and a branch, tag or commit. We clone the actual source code.

Step two

Dependencies are handled for you

At install time, the installer picks the newest runtime that matches your version range and runs on the computer, and installs it in the app's own folder.

Step three

Build for every platform

We package the result as a Windows .exe (NSIS) and a Linux .run and macOS .dmg (Qt Installer Framework).

04  Isolation

Every app gets its own folder

Each app is installed with its own copy of every dependency, in folders with short hashed names. Nothing is shared, so one app can never break another, and uninstalling just deletes the app's folders. Disk space is cheap; broken installs aren't.

Windows   C:\ti\k3m9q2x7v4p8\     the app
          C:\ti\tjfq5rqwnnrx\     its Python 3.12.4
          C:\ti\a7d2hx9q4mbe\     its git 2.46.0
Linux     /opt/ti/tjfq5rqwnnrx/
macOS     /Library/Application Support/ti/tjfq5rqwnnrx/

06  Reuse

Base installers are reusable

Every installer is a base installer plus settings. For example, install_python_x.exe installs the Python package x. The base's code stays the same; only the settings change.

install_python_requests.exe   -> installs the "requests" package
install_python_black.exe      -> installs the "black" package
install_node_prettier.exe     -> installs the "prettier" package
07  Signing

Three ways to ship

Mode A

Signed by us

The fewest security warnings. Settings live in the file name, so renaming the file retargets it and keeps the signature.

Mode B

Signed by you

Your name and icon on the installer itself, with your own certificate and your own reputation.

Mode C

Unsigned

Fully editable. Change what it installs, its name and its icon in your browser, without uploading the file.

08  The promise

Nothing hidden

Every installer, whoever signed it, shows what it will install, where it comes from, what it downloads, where files go and who signed it, before it changes anything. That screen — the one at the top of this page — is not a summary we write afterwards. It is read from the installer's own settings block, so it cannot disagree with what happens next.
