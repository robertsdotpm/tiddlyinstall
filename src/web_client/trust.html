Trust  What is proved, and what is taken on faith

What you are trusting, and why

An installer is a program that changes your computer. This page says exactly which parts of that we can prove to you, which parts you have to take on someone's word, and whose word it is.

The short version

There are two different questions, and they have different answers.

What does it install?
Proved. The runtime it downloads, the exact bytes it expects, where it gets them and every command it runs against them are signed by us before anybody asks for them. The installer checks that signature itself, on your machine, with no internet connection needed.
Is the program itself any good?
Not proved, and we could not honestly claim otherwise. We did not write it and have not read it. That is between you and whoever published it -- which is what a signature on the installer file is for, and why it carries their name and not ours.

Every installer says both of these on its own screen, before it changes anything.

Who wrote which part

An installer is built from two kinds of instruction. Keeping them apart is the whole idea.

We sign what we wrote. Nobody needs us to vouch for the line that starts their program: they wrote it, and they know what it says. Pretending to cover it would make the signature mean less, not more.

How an installer proves it, with no internet

The instructions for putting a runtime on your machine are the same for everybody. Installing Python 3.14 on 64-bit Linux does not depend on which app you are installing. So we can sign those instructions in advance -- long before anyone asks for them -- and hand out a small receipt with each installer.

This is why an installer built entirely inside your browser, with no server involved at all, can still show that what it installs came from us. The browser never needs a secret key, because it is only carrying signatures, never making them.

Two ways to use this, and what each one costs

With our server
You trust the site you are on. It builds installers, signs the instructions, and can be asked at install time whether anything has been withdrawn since. If the page and the server are the same domain, that is one decision, not two -- and the header says Server: this site when it is.
Saved to disk, no server
The page works on its own. It carries a dated, signed copy of everything it needs, and says how old that copy is. What it cannot do is learn anything new: a runtime withdrawn after your copy was saved is not known to it. Installers it builds say so, in those words, rather than staying quiet.

What this page is carrying right now

Not a description -- the actual contents of the file you are reading, checked against its own key as the page loads.

Anything that does not check out is shown as failing and is not used. A signed list we cannot verify counts for nothing, exactly as if it were not here.

Our keys

One key signs everything above. It is public: it is already inside every installer this page builds, and this only makes it readable.

What we cannot prove to you

Worth saying plainly, because a page about trust that only lists its strengths is an advertisement.

  • That the program is safe. We did not write it and have not read it. Install it because you trust whoever published it, not because you trust us.
  • That this page itself is genuine. A page cannot prove that about itself. Drop a copy on the Verify page of a copy you already trust, and it will say whether the two agree.
  • That an unsigned installer file was not tampered with. Compare its SHA-256 with the one shown where you downloaded it. That comparison happens outside the file, which is what makes it worth anything.
  • That we have not changed our minds about something. We keep a record of everything we publish, chained so entries cannot be quietly rewritten -- and every copy of this page in the world carries a fingerprint of that record as of the day it was built. We hold the signing key, so a signature alone could not catch us rewriting history. Copies in other people's hands can.
